# 典型场景

三个典型场景描述 OryxOS 完整形态下的目标用法；核心阶段先交付这些场景所依赖的运行时内核。

## 运维助手

某 SaaS 公司把运维助手接入企业微信。凌晨告警经 webhook 进来：Agent 查日志、交叉比对历史故障库、应用自愈 Skill 重启服务，在值班群里汇报"已自愈，详情见附件"——工程师早晨起来看记录就行。

**OryxOS 在此场景**：渠道接入、Provider 路由、工具调用（SSH / Prometheus / 通知）、记忆（历史故障）、Skill（自愈 runbook）。

## 知识管理助手

法务团队索引合同模板、法规文档、历史案例。员工在 IM 里问："上次 SaaS 协议的数据出境条款怎么处理的？"Agent 检索案例、标注引用来源、给出建议草稿——每个回答可追溯，满足合规要求。

**关键点**：记忆检索准确度与引用可追溯。

## 销售助手

销售拜访前问："明天去 A 公司，我需要知道什么？"Agent 调 CRM connector 拉历史交易、通过 MCP 工具查最新工商信息、提取关键决策人与采购习惯，输出一份客户简报。

**OryxOS 在此场景**：MCP 集成、企业系统 connector、工具编排。

## 从场景到验收

每个核心能力都对应一个验收 Demo——天气问答（LLM + ReAct）、跨重启记忆、零代码 PR 日报、REST 完整会话生命周期、多端点协同。这些 Demo 是核心阶段发布的硬条件。
